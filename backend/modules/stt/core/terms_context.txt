# Qwen3-ASR 컨텍스트 바이어싱용 용어 목록 — 런타임 전용.
#
# ── 2026-08-14: 개발자 타깃 철회에 따라 개발 용어 68개를 제거했다 ──────────────
#
# 이전 목록(78개)은 대상 사용자를 개발팀으로 잡고 만든 것이었다. 제품 방향이
# "일반 회의"로 바뀌면서 그 전제가 사라졌으므로 도메인 용어를 전부 뺐다.
#
# 빼는 것이 손해가 아니라 이득인 근거 — 제거 직전 실측:
#   활성 용어 78개를 우리 모의 회의 대본 5건에 대조한 결과 **실제 등장은 19개(24%)**.
#   도커·쿠버네티스·풀리퀘스트·리팩토링·핸드셰이크 등 59개는 개발자 타깃일 때조차
#   한 번도 발화되지 않았다. 안 나오는 단어는 이득이 0인 반면 비용은 둘 다 낸다:
#     ① 오적용 — 말하지 않은 용어로 잘못 끌려감(terms_context_v2 A/B의 관심사였다)
#     ② 지연  — 목록 길이가 곧 지연이다(실측 204개 0.85초 / 3000개 2.15초)
#
# 그래서 남긴 것은 **회의 그 자체의 어휘**뿐이다. 도메인이 무엇이든 회의라면 나온다.
#
# ⚠️ 이 아홉 개는 취향으로 고른 게 아니라 2026-08-04 5인 모의 회의 대본 대조에서
#    **전부 실제로 오인식된 것들**이다:
#      재논의→재무의/제논이, 결정사항 상태값→일정 상황 상태 값,
#      번복→반복, 할 일→할례
#    특히 "번복"→"반복"은 뜻이 정반대로 뒤집혀 모순 감지에 직접 타격을 준다
#    (결정을 뒤집었다는 문장이 되풀이했다는 문장이 됨). 이건 우리 팀 전용 사정이
#    아니라 한국어 회의 일반의 문제라 타깃과 무관하게 남는다.
#
# 도메인 용어는 이제 정적 목록이 아니라 services/meeting_terms.py가 담당한다 —
# 같은 session_id의 지난 회의록에서 그 팀이 실제로 쓴 단어를 뽑아 넣는다.
# 사람이 미리 예측해 적는 방식보다 어느 도메인에나 맞고, 예산도 같다.
#
# ⚠️ 숫자(포트 번호 등)는 넣지 않는다 — Whisper에서 실측으로 역효과가 확인됐고
#    (없는 숫자로 잘못 끌려감), Qwen도 컨텍스트로 출력 형식/값을 제어하지 못한다는
#    게 확인됐다("숫자는 아라비아 숫자로 표기" 지시문 무효). 숫자 표기는
#    utils/korean_itn.py 후처리가 담당한다.
