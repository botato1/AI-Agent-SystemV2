# 프론트엔드 컴포넌트 구조 회의록

일시: 2026-07-13
참석: 김나연, 문지수, 이승주

## 논의 내용

오늘 회의에서는 프론트엔드 컴포넌트 구조를 어떻게 잡을지에 대해 논의했다.
현재 페이지 수가 많지 않아 처음에는 페이지 단위로 컴포넌트를 나누는 방식도 고려했으나,
추후 기능이 늘어날 것을 감안하여 도메인 단위로 폴더를 구성하는 방향으로 의견이 모였다.

상태 관리 라이브러리에 대해서도 논의가 있었다. Redux를 사용할지, 아니면 좀 더 가벼운
Zustand를 사용할지에 대해 이야기했는데, 현재 프로젝트 규모를 고려했을 때 Zustand가
러닝커브도 낮고 보일러플레이트도 적어 적합하다는 의견이 우세했다. 다만 추후 상태 관리가
복잡해질 경우 Redux로 전환할 가능성도 열어두기로 했다.

스타일링 방식은 기존에 사용하던 Tailwind CSS를 그대로 유지하기로 했으며, 별도의 변경 사항은
없었다.

컴포넌트 네이밍 컨벤션에 대한 논의도 있었다. 기존에는 일관성 없이 작성된 컴포넌트들이
있었는데, 앞으로는 PascalCase로 통일하고, 공용 컴포넌트는 별도의 shared 디렉토리에 모아
관리하기로 했다.

## 결정 사항

- 컴포넌트 구조는 도메인 단위로 폴더 구성
- 상태 관리는 Zustand 사용 (추후 필요 시 Redux 전환 검토)
- 스타일링은 기존 Tailwind CSS 유지
- 컴포넌트 네이밍은 PascalCase로 통일, 공용 컴포넌트는 shared 디렉토리로 분리
