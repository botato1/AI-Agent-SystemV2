# 가상 회의 데이터 — 실시간 판단 파이프라인 테스트용

승주(RAG/LLM) 요청으로 만든 테스트 픽스처. 하나의 이어지는 백엔드 설계 스토리라인으로
7개 시나리오를 전부 커버함 (baseline 1개 + 시나리오 6개, 3번/6번은 요청대로 한 회의에 병합).

## 파일 ↔ 시나리오 매핑

| 파일 | 시나리오 | 확인 포인트 |
|---|---|---|
| `01_baseline_초기설계.txt` | (기준 회의, 이후 전부가 참조함) | DB=PostgreSQL, Auth=JWT, 캐싱=Redis, 배포=AWS 결정 |
| `02_모순_DB변경.txt` | 1. 재결정(모순) | DB를 MongoDB로 근거 없이 변경 → 모순 팝업 떠야 함 |
| `03_정당한변경_인증방식.txt` | 2. 정당한 변경 | Auth를 OAuth2로 변경, 근거 명확(소셜로그인 요구사항) → 팝업 안 떠야 함 |
| `04_리마인더_반복언급.txt` | 3. 결정 리마인더 + 6. 여러명 반복언급 | 배포 방식 질문(새 값 없음)→리마인더 / 캐싱 방식 3명이 다른 값 언급→팝업 중복 안 되는지 |
| `05_보류_실시간알림.txt` | 4. 보류 | 웹소켓 vs 폴링, 결론 없이 "다음에 다시" |
| `06_재확인_DB.txt` | 5. 재확인 | DB(MongoDB) 그대로 유지 재확인, 변경 없음 |
| `07_문서업로드_프론트엔드구조.md` | 7. 텍스트 직접 업로드용 | 화자 라벨 없는 일반 회의록 문서 형식 |

## 스토리라인 순서 (시간순)

01(초기 결정) → 02(DB 모순 변경) → 03(Auth 정당한 변경) → 04(리마인더+반복언급) → 05(보류) → 06(재확인)
07은 독립된 다른 주제(프론트엔드) 회의라 시간 순서에 안 묶임.

## 등장 인물

이준오(STT), 가동현(에이전트/모순감지), 문지수(백엔드), 정승현(문서/OCR), 이승주(RAG/LLM), 김나연(프론트엔드) — 실제 팀원 이름 그대로 사용.
