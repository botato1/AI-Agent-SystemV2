# 모의 회의 대본 — 검색 품질 개선 스프린트 (4인, 가동현 불참)
#
# 이 대본은 **문장 단위 분할 검증**을 위해 만들었다. 확인하려는 것:
#
#  ① 한 사람이 여러 문장을 쉬지 않고 이어 말하는 구간
#     → 예전에는 이게 통째로 세그먼트 하나가 됐다(최장 28초).
#       분할이 걸리면 문장마다 세그먼트가 나뉘고 time_estimated=true가 붙는다.
#     ★ 표시가 붙은 줄은 **문장 사이에 쉬지 말고 이어서** 읽을 것. 여기가 핵심이다.
#     ★는 읽지 않는다. 채점 시 정규화 단계에서 자동으로 제거되므로 CER에 영향이 없다.
#
#  ② 짧은 맞장구
#     → "네." 같은 조각이 따로 떨어지지 않고 앞 문장에 붙는지 본다.
#
#  ③ 결정 번복 (17~19번 줄)
#     → 모순 감지 파이프라인 입력용. "확정" 뒤에 뒤집는 구조다.
#
# 읽는 요령
#  - 평소 회의 속도로. 빨리 읽으면 인식이 무너져 검증이 안 된다(실측: CER 32%).
#  - 화자가 바뀔 때는 0.5초쯤 쉰다. ★ 줄 안에서는 쉬지 않는다.
#  - 참석자 목소리를 미리 등록하고 attendees에 4명을 다 넘길 것.
#    등록이 1명뿐이면 화자가 전부 미상으로 나오고, 그건 이 검증과 별개 문제다.

문지수: 오늘은 검색 품질 개선 스프린트 계획을 잡으려고 모였어요.
문지수: ★ 지난주에 사용자 문의를 쭉 봤는데 검색 결과가 엉뚱하다는 얘기가 제일 많았어요. 특히 두 단어 이상 넣으면 관련 없는 게 위로 올라온다고 하더라고요. 그래서 이번 스프린트는 검색 하나에 집중하는 게 맞다고 봅니다.
이승주: 저도 같은 생각이에요.
김나연: ★ 원인은 대충 짐작이 가요. 지금 임베딩 모델이 짧은 질의에 약해요. 두 단어짜리 질의는 벡터가 뭉개져서 유사도가 거의 비슷하게 나오거든요. 그래서 순서가 사실상 무작위가 됩니다.
문지수: 그러면 모델을 바꾸는 게 답인가요?
김나연: 바꾸는 것도 방법인데 파인튜닝이 더 빠를 것 같아요.
이승주: ★ 파인튜닝은 데이터가 문제예요. 지금 우리가 가진 검색 로그는 클릭 기록이 안 붙어 있어요. 정답 쌍을 만들려면 사람이 직접 라벨링을 해야 하는데 그게 최소 2주는 걸립니다.
문지수: 2주면 이번 스프린트 안에는 못 끝내네요.
김나연: 네.
문지수: 그럼 이번 스프린트는 리랭킹만 붙이고 모델 교체는 다음으로 미루겠습니다.
이승주: 좋습니다. 리랭킹은 제가 맡을게요.
이준오: ★ 잠깐만요. 리랭킹을 붙이면 응답 시간이 늘어나지 않나요? 지금도 검색이 느리다는 문의가 있었어요. 레이턴시가 더 늘면 그것대로 불만이 생길 것 같은데요.
이승주: 그건 캐싱으로 어느 정도 잡을 수 있어요.
이준오: 캐싱이 안 먹는 질의가 문제죠.
문지수: 음, 그러면 결정을 다시 볼까요.
이준오: ★ 저는 리랭킹 대신 질의 확장을 먼저 해보는 게 낫다고 봐요. 두 단어 질의에 동의어를 붙여서 넓히는 거죠. 이건 응답 시간에 거의 영향이 없고 하루면 붙일 수 있어요.
김나연: 아 그게 낫겠네요.
문지수: 그럼 아까 결정을 뒤집을게요. 리랭킹은 보류하고 질의 확장을 먼저 넣는 걸로 확정하겠습니다.
이승주: 네 알겠습니다.
문지수: ★ 정리하면 이번 스프린트는 질의 확장 하나만 합니다. 리랭킹과 모델 교체는 다음 스프린트로 넘기고요. 라벨링은 이번 주부터 준비만 시작해주세요.
김나연: 라벨링 기준은 제가 초안 잡아서 공유할게요.
이준오: 저는 질의 확장 쪽 동의어 사전을 정리하겠습니다.
문지수: 좋습니다. 오늘 결정된 건 두 가지예요. 수고하셨습니다.
