# 배포본 기준선 실측용 모의 회의 대본 (5인)
#
# 왜 필요한가 (2026-08-20): 오늘 실시간 경로에 두 가지를 고쳤다
#  (경계 패딩 TURN_PAD_SEC, 화자 전환 시 첫 턴 순방향 흡수) — 이 수정이 반영된
#  배포본의 cpCER을 아직 한 번도 재지 않았다. 이게 없으면 이후 무엇을 바꿔도
#  "좋아졌다"를 증명할 기준이 없다.
#
# 확인하려는 것 — NEXT.md #6과 동일한 목적, 이번엔 실제로 겹침을 넣는다:
#  ① 오늘 고친 경계 패딩이 실제로 말머리 잘림을 줄이는지
#     ★ 표시 줄은 문장 사이에 쉬지 말고 이어 읽는다 — 화자 전환이 침묵 없이 이어지는
#       상황(오늘 버그 리포트의 재현 조건)을 만든다.
#  ② [겹침] 표시 줄은 **바로 앞 화자의 말이 끝나기 전에 겹쳐서** 말한다.
#     겹침은 여태 한 번도 제대로 측정한 적이 없다 — 이번이 처음이다.
#  ③ 짧은 맞장구("네.", "좋아요.")가 앞 문장에 잘 붙는지
#
# 읽는 요령
#  - 평소 회의 속도로 읽는다. 빨리 읽으면 인식이 무너져 검증이 안 된다.
#  - ★ 줄 안에서는 절대 쉬지 않는다. 화자가 바뀔 때만 보통 0.5초 쉰다
#    (단, [겹침] 줄은 예외 — 앞사람 말이 끝나기 전에 끼어든다).
#  - 참석자 5명 목소리를 전부 미리 등록하고, 회의 시작 시 attendees에 5명 다 체크할 것.
#  - [겹침] 줄은 정확히 "누구 말 위에" 겹치는지 읽는 사람들끼리 미리 맞추고 시작한다
#    (예: 아래 12번 줄은 11번 줄이 아직 안 끝났을 때 끼어든다).

문지수: 오늘은 배포본 기준선을 재기 위한 모의 회의를 진행하겠습니다.
문지수: ★ 지난주에 반영한 실시간 화자 인식 수정 두 가지를 오늘 실제 환경에서 확인하려고 해요. 하나는 화자가 바뀌는 지점에서 말머리가 잘리던 문제고, 다른 하나는 아주 짧은 발화가 화자 미상으로 혼자 남던 문제입니다.
이승주: 네.
가동현: 좋습니다. 저도 궁금했던 부분이에요.
김나연: ★ 그럼 순서대로 가볼게요. 먼저 화자 전환 구간부터 확인하고, 그다음에 겹쳐 말하는 구간을 넣어서 진행하겠습니다. 겹침은 이번이 처음 재는 거라 다들 미리 타이밍 맞춰주세요.
[겹침] 이준오: 저는 준비됐습니다.
이승주: 그럼 바로 시작할까요.
가동현: ★ 지난 회의록 보니까 화자 미상이 자주 뜨는 구간이 대부분 화자 전환 직후였어요. 한 사람이 말을 끝내자마자 다음 사람이 바로 이어서 말하면 그 첫 몇 글자가 따로 떨어져 나갔거든요.
문지수: 맞아요, 그게 오늘 고친 부분이죠.
[겹침] 김나연: 맞아요.
이준오: ★ 짧은 발화 문제도 같이 보죠. "네"나 "좋아요" 같은 맞장구가 독립된 세그먼트로 떨어지면서 화자 미상으로 남는 경우가 많았어요. 이것도 오늘 수정에 포함된 부분입니다.
이승주: 네, 확인해보겠습니다.
가동현: 그럼 이제 겹쳐 말하는 구간을 한번 만들어볼게요.
문지수: ★ 제가 먼저 발표 일정 얘기를 꺼낼 텐데, 얘기 도중에 한 분이 끼어들어 주세요. 발표는 다음 주 화요일 오전으로 잡혀 있고 그 전까지 성능 개선을 마쳐야 하는 상황입니다.
[겹침] 이준오: 잠깐만요, 화요일이면 시간이 너무 촉박한데요.
김나연: 그러게요, 저도 걱정되네요.
문지수: 음, 그럼 일정을 다시 볼까요.
가동현: ★ 저는 일정보다 범위를 줄이는 게 낫다고 봐요. 전부 다 손대려고 하지 말고 화자 인식 쪽만 집중해서 먼저 끝내는 게 현실적일 것 같습니다.
이승주: 아 그게 낫겠네요.
문지수: 그럼 아까 얘기는 보류하고, 범위를 화자 인식으로 좁히는 걸로 확정하겠습니다.

[겹침] 가동현: 저도 동의합니다.
